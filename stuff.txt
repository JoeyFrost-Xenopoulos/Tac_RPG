Comprehensive Code Review: my_game_2 (LÖVE2D / Fire Emblem: Sacred Stones Replica)
Scope reviewed: main.lua, config.lua, engine modules, combat modules, unit system, UI modules, world/map modules, audio, manager mixins, and unit definitions. ~3,500 lines across ~50 files.

1.7 Color swap pixel-by-pixel on every load
File/Line: modules/manager/utils.lua:8-35

applySwapsToImageData iterates every pixel with nested loops and per-pixel getPixel/setPixel. For 192×192 sprites this runs ~37K iterations per swap. Multiple units × multiple swaps = noticeable hitch on love.load.

Fix: Pre-process all palette swaps during load, cache the resulting Image objects, and never regenerate them per-instance. Consider using a shader for runtime palette swaps instead.

3. Code Quality & Best Practices
3.1 Global mutable state
Every module.

Input = require(...), Mouse = require(...), etc., all mutate module-level tables. This creates implicit coupling, makes tests impossible without global mocking, and risks name collisions.

Fix: Adopt a consistent pattern. Either:

Pure modules returning tables (local M = {}; return M)
Or an explicit Context object passed to init:
local Input = {}
function Input.init(ctx) ctx.input = Input end
return Input
3.2 Inconsistent return patterns
modules/engine/input.lua returns Input table
modules/engine/mouse.lua returns Mouse table
modules/manager/core.lua returns attach function
modules/units/base/init.lua returns BaseUnit class
modules/units/soldier.lua returns a hybrid table + singleton
Fix: Standardize on one pattern. Given the existing mixin architecture, returning attach functions for mixins and tables for standalone modules is acceptable, but it should be documented and consistent.

3.3 Magic numbers
Examples:

modules/engine/camera_manager.lua:48 — panSpeed = 400
modules/engine/camera_manager.lua:21 — zoomSpeed = 0.1
modules/engine/movement.lua:27 — moveDuration = 0.25
modules/combat/battle_state.lua:11-13 — runDuration = 0.8, etc.
modules/world/clouds.lua:13-14 — 18 * 64, 15 * 64
Fix: Group into a Config table or named constants:

local CONFIG = {
    PAN_SPEED = 400,
    ZOOM_SPEED = 0.1,
    MOVE_DURATION = 0.25,
    MAP_WIDTH_TILES = 18,
    MAP_HEIGHT_TILES = 15,
}
3.4 Long functions with deep nesting
File/Line: modules/engine/mouse.lua:16-148 — 132-line Mouse.pressed with 7 levels of nesting.

Fix: Decompose into state handler functions:

local stateHandlers = {
    idle = function(...) ... end,
    selectingAttack = function(...) ... end,
    menu = function(...) ... end,
}
function Mouse.pressed(x, y, button)
    local handler = stateHandlers[UnitManager.state] or stateHandlers.idle
    handler(x, y, button)
end
3.5 String-based state machine
File/Line: modules/units/manager.lua:5 — state = "idle"

A bare string with no enum or validation. Typos like "idel" silently break behavior.

Fix:

local UnitState = { IDLE="idle", MOVING="moving", MENU="menu", ... }
UnitManager.state = UnitState.IDLE
3.6 goto usage
Files/Lines:

modules/ui/menu.lua:149 (goto continue)
modules/world/leaf.lua:124 (goto continue)
Lua 5.2+ supports goto, but it's an anti-pattern for loop control.

Fix: Extract the loop body into a function or use if not shouldRemove then ... end guard clauses.

3.8 Inconsistent naming
isUnitDead vs isDead (set on unit in battle_attack_helpers.lua:123, checked via Utils.isUnitDead)
hasActed vs hasMoveOrderQueued
selectingAttack vs combatSummary
Fix: Adopt a naming convention (e.g., isX for booleans, hasX for state flags).

3.9 Battle inherits from State via alias
File/Line: modules/combat/battle.lua:13 — local Battle = State

This makes Battle literally the same table as State, so any mutation to Battle.visible mutates State.visible globally. If State is ever reloaded, Battle breaks.

Fix: Use composition or proper inheritance:

local Battle = setmetatable({}, {__index = State})
3.10 Inconsistent error handling
File/Line: modules/units/unit_spawner.lua:42,54 — error("Variant '" .. variant .. "' not found")

Hard crashes on config typos. A malformed map config should log a warning and skip the unit, not crash the game.

Fix:

print("[UnitSpawner] Warning: variant '" .. variant .. "' not found, skipping")
return nil, function() end
4. Bug Detection
4.1 Attack.performAttack counterattack logic is split and confusing
File/Line: modules/engine/attack.lua:33-71

performAttack applies damage and then checks canBeDoubleAttacked for a counterattack, but turn.lua:169-188 also initiates Battle.startBattle for enemy attacks. This means counterattacks can fire twice or be skipped depending on code path.

Fix: Centralize all combat resolution in CombatSystem or Battle. Attack.performAttack should only calculate and apply damage; battle orchestration belongs in Battle.

4.2 getEnemiesInRange ignores minRange

local dist = math.abs(unit.tileX - attacker.tileX) + math.abs(unit.tileY - attacker.tileY)
if dist >= minRange and dist <= attackRange then
Wait — this actually does check minRange (line 15: dist >= minRange). However, Attack.canAttack and Mouse.pressed both call getEnemiesInRange which correctly uses minRange. No bug here — this was already correct.

4.3 TurnAI.findNearestEnemyUnit is misnamed / wrong scope
File/Line: modules/engine/turn_ai.lua:21-37

for _, unit in ipairs(UnitManager.units) do
    if unit.isPlayer then
The function name says "find nearest enemy" but it finds the nearest player unit. If called from a player unit context, it would return the nearest player (self/allies), not an enemy.

Fix: Rename to findNearestTarget or make the filter parameterized:

function TurnAI.findNearestUnit(fromUnit, predicate)
    local best, bestDist = nil, math.huge
    for _, unit in ipairs(UnitManager.units) do
        if unit ~= fromUnit and predicate(unit) then
            local d = manhattanDistance(...)
            if d < bestDist then best, bestDist = unit, d end
        end
    end
    return best
end
4.4 Map.canMove slope logic may be inverted
File/Line: modules/world/map.lua:109-116

if fromHeight == 0.5 or toHeight == 0.5 then
    return true
end
if (fromHeight == 0 and toHeight == 1) or (fromHeight == 1 and toHeight == 0) then
    return false
end
return false
Bot_Slope (height 0.5) is the bottom of a hill. In Fire Emblem, you can only traverse slopes in one direction (up). This code allows movement from a slope tile unconditionally, which could let units walk off the back of a hill.

Fix: Validate slope direction explicitly:

if fromHeight == 0.5 then
    return toHeight == 0  -- can only go down from bot slope
end
if toHeight == 0.5 then
    return fromHeight == 1  -- can only go onto bot slope from top
end

4.7 TurnManager.endTurn mutates state mid-update
File/Line: modules/engine/turn.lua:211-224

function TurnManager.endTurn()
    ...
    if TurnManager.currentTurn == "player" then
        TurnManager.currentTurn = "enemy"
        TurnManager.startTurn()
    else
        TurnManager.currentTurn = "player"
        TurnManager.startTurn()
        TurnCounter.incrementTurn()
    end
end
endTurn → startTurn → show("Player Turn") → which may trigger update callbacks. This can cause nested update cycles or missed input events.

Fix: Make endTurn and startTurn idempotent and defer overlay display to the next frame:

function TurnManager.endTurn()
    TurnManager.pendingTurnSwitch = true
end

function TurnManager.update(dt)
    if TurnManager.pendingTurnSwitch then
        TurnManager.pendingTurnSwitch = false
        TurnManager._executeTurnSwitch()
    end
end

4.9 CameraManager.screenToWorld ignores rotation

4.15 turn_ai.lua moveEnemyToward uses getUnitAtTile inconsistently
File/Line: modules/engine/turn_ai.lua:214-222

local occupying = getUnitAtTile(finalPos.x, finalPos.y, enemyUnit)
while occupying do
    bestStep = bestStep - 1
    ...
    occupying = getUnitAtTile(finalPos.x, finalPos.y, enemyUnit)
end
The while occupying loop can decrement bestStep to 0 and then access path[1], which is the starting tile. The unit would try to "move" to its own position, which MovementEngine may not handle gracefully.

Fix: Break before bestStep <= 0:

while occupying and bestStep > 0 do
    bestStep = bestStep - 1
    ...
end
if bestStep <= 0 then return false end
